# 产品判断原则、成长记录与新对话交接固化

日期：2026-07-25

## 1. 背景

version 13 全量生产切换已经完成、提交、push 并停止等待产品负责人验收。本轮是独立文档治理任务，只把近期产品负责人与 Claude/GPT 讨论中已经确定的长期判断原则、成长记录、新对话交接方法和阶段验收规则写回仓库。

本轮不改变当前产品主线。当前唯一下一步仍以 `NEXT_STEP.md` 为准：等待产品负责人验收 version 13 全量生产切换与第 3 阶段生产结果。

## 2. 六条原则

本轮在 `PRINCIPLES.md` 固化或完善六条原则：

1. 简单模式与细致模式切换：默认直接执行；遇到验证码、反爬、登录授权、权限、安全、法律或合规边界等技术保护墙时切换细致模式，不硬闯、不绕过；遇到公开但分散的信息时继续简单直接地采集、比较、整理和汇总。备份先行、小流量灰度、真实调用前核对、异常即停和保留回滚能力，是细致模式在项目中的实际应用。
2. 单任务推进：产品负责人可以在思考层面同时关注多个方向，但执行层面任何时候只允许一条任务线真正开工。新想法先记录，当前任务完成、验收并停止后才能开始下一任务。
3. 优先借用成熟生态：AI Workbench 调度模型、Agent、成熟工具和未来执行能力，不为证明技术能力重复造轮子。信息收集、用户反馈、安全扫描、日志监控、支付能力和未来物理执行工具也优先复用成熟产品和开源工具。
4. 个人支付与产品支付分离：个人信用卡、借记卡、Visa 卡和个人 AI 工具订阅支付渠道属于产品负责人个人事务；AI Workbench 向用户收款的支付系统属于未来产品能力，当前不开发。
5. 角色分工与阶段验收：Codex 是执行者和证据生产者，不是最终验收人；Claude/GPT 独立验收对话只能基于其实际可访问的 GitHub 证据审计；产品负责人决定优先级、风险接受、阶段是否通过和是否进入下一阶段。
6. 防御性安全与攻击能力边界：允许并应当建设密钥保护、限流、钱包刹车、紧急关闭、Prompt Injection 防护、依赖漏洞检查、CVE 跟踪、安装包完整性检查、Secret 扫描、日志脱敏、权限最小化、备份、灰度和回滚；禁止为攻击他人系统、绕过验证码/权限/访问控制、盗取凭据或破坏性工具开发能力。

## 3. 产品负责人长期判断框架

本轮在 `THINKING.md` 增加“产品负责人长期判断框架”：

- 产品与世界交互：通过合法方式获取公开信息、比较可靠来源、收集真实用户反馈、观察模型/Agent/工具生态变化，用真实结果修正产品判断。
- 个人成长与产品成长分开：产品负责人可以持续学习技术、经济与支付工具、信息获取、具身智能、生态协作和产品判断，但学习方向不等于产品立即开发任务。
- 产品延伸路径：主要通过接入模型、Agent、成熟工具、信息来源、反馈机制和未来物理执行能力延伸；核心价值是调度、排序、控成本、控风险和验收结果。
- 建构生态：先建立安全、预算和可回滚底座，再找到真实用户和真实问题，再接入能解决问题的成熟执行能力。
- 当前顺序：完成钱包刹车和生产安全阶段，做阶段性独立验收，找到真实用户，收集真实问题和反馈，再决定信息收集、模型分层、上下文压缩或其他模块优先级。

## 4. GROWTH_LOG 新增项目

本轮在 `GROWTH_LOG.md` 追加五类记录：

- 个人独立支付工具：待研究，属于个人学习和个人事务，不属于 AI Workbench 当前产品开发。
- 具身智能：长期了解，当前不开工。
- 信息与用户反馈情报能力：已确认必要，排队等待，当前不开工；启动时优先复用成熟产品和开源工具，并遵守平台、授权、隐私、验证码和反爬边界。
- 防御性产品安全加固：重要，等待排期，当前不开工；只做产品防御，不开发攻击他人系统的能力。
- 产品负责人持续成长：持续记录，不直接转化为并行任务。

## 5. 五份默认必读文件

新对话默认必读文件从三份扩展为五份：

1. `AI-Workbench-Handoff.md`
2. `NEXT_STEP.md`
3. `THINKING.md`
4. `PRINCIPLES.md`
5. `GROWTH_LOG.md`

具体验收时再读取对应 `verification/<task>/summary.json`、`report.md`、必要的 `commands.log`、对应 commit 和 Git diff。新对话不默认读取全部 verification 目录。

## 6. 任务验收与阶段验收区别

执行验收是 Codex 单轮任务完成后的自检和交付，必须给出执行状态、修改内容、未做事项、测试结果、verification 路径、commit、push、工作区 clean，并停止等待产品负责人。

阶段验收是完整产品阶段结束时的独立验收，必须从 GitHub 读取证据，交叉核对代码、测试、verification 和权威文档，输出已完成、未完成、严重阻塞、非阻塞问题、`PASS / CONDITIONAL_PASS / BLOCKED` 结论，以及是否允许结束阶段。

阶段没有通过独立验收和产品负责人批准，不得宣布阶段结束。

## 7. 角色分工

- Codex：执行本地和生产操作、修改代码和文档、运行测试、生成 verification 证据、commit 和 push、完成后停止。
- Claude/GPT：读取已 push 到 GitHub 的证据，检查 commit、diff、verification 和权威文档，输出独立审计结论。只连接 GitHub 的对话不能声称直接查看本地电脑、Cloudflare 实时控制台、实时 D1、Secrets 或本地环境变量。
- 产品负责人：决定产品优先级、批准执行范围、决定是否接受风险、决定阶段是否通过、决定是否进入下一阶段。

## 8. 防御性网络安全边界

允许了解公开攻击思路和漏洞分析，用于制定防御措施。任何实际实现都必须服务于保护自己的产品和用户，并保持合法、授权和可审计。

禁止把 AI Workbench 发展成具备主动攻击能力的工具。

本轮确认并保持当前 `NEXT_STEP.md` 唯一产品下一步不变：
