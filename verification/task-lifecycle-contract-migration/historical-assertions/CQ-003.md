```js
{

  const interpreter = new TaskInterpreter({ model: models });
```

## 原测试目的

原用例同时验证：

1. TaskInterpreter第一次和唯一一次纠正均无效时，正式抛出Task Interpreter错误，而不是伪装为clarification；
2. Runtime已存在的业务Task通过正式错误路径持久化为`failed`。

## 为什么必须拆分

第一部分属于TaskInterpreter组件的调用次数、受限纠正和错误语义；第二部分属于Runtime的Task创建时机、状态机持久化和终态重放。两者处于不同架构边界，合并测试会把组件失败错误地绑定到历史Runtime入口。
